## Machine-readable daemon status

`engram daemon status --json` emits schema version 1 with:

- `running`, `ready`, project, port, and PID;
- the live health identity and spawn-time executable metadata;
- the invoking CLI path, version, executable SHA-256, health schema, MCP contract, MCP tool hash,
  and MCP protocol;
- a deterministic `matched`, `degraded`, or `drifted` runtime-attestation state plus reasons.

Against the live global daemon it returned `running=true`, `ready=true`, and
`runtime_attestation.status=drifted`. Reasons included the 0.2.0/0.2.3 version mismatch, different
spawn/current executable paths, legacy spawn metadata without an executable hash, and absent live
health-schema, MCP-contract, MCP-tool-hash, protocol, authentication, and datastore-readiness
fields. Against a fresh isolated `ENGRAM_HOME`, it returned valid JSON with `running=false`,
`ready=false`, explicit current candidate identity, and null live/spawn/attestation fields.

These are current-environment findings, not permission to rewrite user-owned host configuration.
Adapter installation, host restart, and daemon replacement remain separate approval gates.
