## What the failure distinguishes

1. **Dense is the next candidate-generation direction.** It recalled every relevant record and
   improved MRR by 0.3385 over the current lexical arm. It achieved 5/5 semantic-paraphrase
   recall, where current lexical achieved 2/5, and 3/3 lifecycle-correction recall, where current
   lexical achieved 1/3.
2. **Do not choose RRF from this evidence.** Fusion preserved recall but reduced MRR from 0.9115
   to 0.8229. The current lexical ranker often reinforced distractors rather than the dense result.
3. **Do not ship the generic lifecycle boost.** It produced no aggregate gain over RRF and also
   promoted the integration-test successor for the ordinary `deploy queue worker` query because
   the inactive procedure shared broad terms. Explicit lifecycle traversal remains useful, but
   its trigger must be narrower than token-overlap coverage.
4. **Do not use a single similarity threshold as the abstention mechanism.** Relevant top scores
   ranged as low as 0.1918, while true no-result top scores reached 0.2508. All five semantic
   paraphrases fell below the frozen 0.35 threshold and were discarded. The score distributions
   overlap, so threshold tuning cannot solve the underlying distinction.
5. **Opaque scope canaries are separable.** Exact scoped-cue validation correctly abstained on
   both cross-project canary queries even though their top dense similarities were 0.4392 and
   0.3641. That rule is useful as a narrow safety guard, not a general relevance classifier.

## Decision and next experiment

Treat retrieval and application as separate stages:

1. use scope-filtered dense retrieval to discover a small evidence-backed candidate set;
2. preserve lifecycle, provenance, status, and scope metadata in every candidate;
3. make a separately evaluated applicability/abstention decision before a candidate can enter an
   automatic context packet;
4. keep low-confidence candidates inspectable as search results rather than silently injecting
   them or pretending no result exists.

The next preregistered evaluation should test selective prediction on held-out queries. It should
compare an evidence-grounded applicability check (and, if available locally, a frozen reranker or
entailment model) against simple lexical-agreement and margin baselines. Calibration and testing
must use disjoint query sets. Until such a gate passes, dense retrieval is justified for candidate
discovery only—not automatic memory application.

Host-native task success is still a separate provider-backed evaluation and remains approval
gated.
