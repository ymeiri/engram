## Final independent findings

All three final reviewers independently found these boundaries closed:

1. **Exact scope and first authority.** The four classes are fixed and ordered. Acquisition,
   qualification A and qualification B first bind at exact `post-child-0`; host-validation lints
   first binds at exact `post-child-5`. Both qualification phase names are explicit. No basename,
   prefix, glob, caller profile or fresh observation can select or reset a class.
2. **Implementable stable identity.** The carrier retains marker and tag device/inode, ownership,
   flags and birthtime plus the tag's link count, size and digest; each closed class fixes the
   marker-directory and tag-regular-file types. Marker link count, size, atime, mtime, ctime and
   entries, tag atime/mtime/ctime and both object modes are excluded from equality. Exact current
   modes, types, profiles, ACLs, tag content and logical-tree state remain mandatory at every
   phase/boundary, so the accepted same-inode host seal succeeds while substitution fails.
3. **Cargo creation boundary.** The first row can arise only after pre-child absence and the exact
   successful final post-child validation. A temporary candidate, pre-existing final path, rename
   fallback, failed tag or residual sibling cannot become authority. Pinned Cargo/tempfile source,
   sole-writer and callsite proof remain mandatory implementation-preflight inputs.
4. **Canonical cross-process carrier.** The xattr sidecar is unchanged. The metadata wrapper gains
   one exact count header and a closed ordered marker-row suffix; its existing digest covers the
   entire amended wrapper. Counts, integer spelling, paths, order and field bounds are canonical.
5. **Phase and graph continuity.** Each later process loads the exact predecessor wrapper/digest
   and compares current held-descriptor observations to its rows. `graph-finalize` emits no wrapper
   but consumes the one prior carrier; `source-audit` names that same predecessor and cannot infer
   or reset a missing identity.
6. **Unchanged result and completion schemas.** Ordinary `result.json` schemas and the
   `darwin_metadata_checks` bijection remain unchanged. Marker validation is terminal before a
   successful completion scan and emits no marker/tag object row; the accepted evidence-parent,
   phase-directory and evidence-leaf TSV classes, count, order, fields, sidecars and applicability
   table remain unchanged.
7. **Finite trust and execution boundary.** The addendum chain is exactly six records: Darwin
   addendum/review, launcher amendment/review, then marker amendment/review. The base freeze remains
   a separate protected authority. The single launcher-source semantic projection gains no field

   audit or execution authority is added.
8. **Required implementation evidence.** The later combined preflight must bind exact carrier
   producer/consumer dominance, applicability and predecessor tables, descriptor continuity,
