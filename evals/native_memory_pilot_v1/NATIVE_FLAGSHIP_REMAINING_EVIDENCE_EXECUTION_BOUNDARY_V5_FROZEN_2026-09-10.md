## 4. Acyclic lifecycle and trust boundary

The only valid ordering is:

```text
D -> I -> U -> Q -> P -> M[i] -> C[i] -> T[i] -> K[i] -> H[i]
```

- `D`: exact V5 design plus advisory reviews with no unresolved P0/P1.
- `I`: append-only implementation freeze selected by the honest coordinator. It binds exact Rust
  source closure, scorer/tests, host binary, guest binaries, image, static runtime template,
  provider clients, date-versioned Claude model, authentication methods, sandbox policies, and
  schemas. I is independent of U, Q, P, and every dynamic manifest.
- `U`: authentic external user event accepting exact D and I and one bounded future plan within
  them. The local U receipt is a non-authoritative audit cache.
- `Q`: provider-free validation of exactly I's already-selected mechanisms. Q may bind D, I, and U;
  it cannot choose a method or refer to a future P.
- `P`: one exact run plan created after Q. P binds D, I, U-receipt digest, Q-receipt digest, the
  protocol, static runtime template, 30 admissions, limits, object names, and schemas.
- `M[i]`: exact per-admission manifest, durably published before its claim. It binds P and current
  dynamic identities; P never binds a future M digest.
- `C[i]`: one durable, permanently spending admission claim bound to M[i].
- `T[i]`: pre-cleanup terminal evidence/receipt.
- `K[i]`: cleanup, no-object, or indeterminate-quarantine disposition receipt.
- `H[i]`: derived evidence-chain head for the next admission.

No edge points backward. The static runtime template in I contains no plan hash, U/Q receipt, chain
head, or admission output. Q never binds P. P binds U and Q, not vice versa. M and C cannot authorize
their parents. Hash identity is not authority.

One small exact-hash Rust evaluator implements scheduling, manifests, claims, Docker admission,
watchdog mode, trace validation, scoring, and append-only reporting. Pure exact-hash parsing/scoring
and `native_successor_core` O_EXCL/fsync primitives may be reused only when included in I. Model
output is bounded data and is never loaded or executed.

## 11. Revocation and spend

## 12. Budget and scorer semantics

Protocol `claude_budget_cents=50` and `claude_authorized_ceiling_cents=50` are historical runner
bookkeeping allocation fields, not an enforceable monetary ceiling and not a V5 safety claim. The
standing user instruction removes a dollar-budget approval gate. V5 instead binds exactly 12 Claude
harness admissions, launched one at a time, with `claude_max_turns=12`, exact host deadlines, and no
extra admission. Actual USD cost, internal requests, and retries are recorded when authenticated
and observable, otherwise `unavailable`; there is no USD, token, or hidden-retry ceiling claim.

The protocol resource fields are post-hoc evaluation-only matched-delta eligibility gates, not
preemptive teaching/activation limits. Current scorer semantics, to be frozen exactly in I, are:

- within the same host, case, and repetition, Engram is paired to Native and Both is separately
  paired to Native;
- combined delta is whole Both minus Native, never Both minus Engram and never Engram-only overhead;
- token delta is treatment total minus native total;
- Claude total is input + cache-creation input + cache-read input + output;
- Codex total is reported input + output; cached input is a subset and reasoning is recorded but not
  added;
- runner duration is `provider_completed_unix_ms - provider_started_unix_ms`;
- a signed delta greater than 50000 tokens or 30000 ms fails; equal, zero, or negative passes;
- missing telemetry on either side fails closed; and
- all-resource pass requires every Engram/Native and Both/Native pair on both hosts, with Engram
  result bytes also limited to 8192 per call and 16384 per treatment lane.

The dedicated stale report imports this resource gate but makes no incremental-value claim. V5
must not reinterpret the baseline or present resource eligibility as a causal product result.

## 13. Outcome progression, cleanup, and reports

After an admission stops, the evaluator seals raw streams, native trace, structured output, tool
observations, resource/provider metadata, input/runtime revalidation, Docker inspect, watchdog
transcript, and proven-termination evidence as T. Only then may it create an O_EXCL cleanup
authorization for the exact stopped container/network IDs bound to C/T. Cleanup permits only
disconnect, stop/kill, and remove those exact ephemeral objects. It permits no create/start,
wildcard/prune, image/volume/auth/evidence deletion, or cross-epoch action. K records cleaned,
no-object, or indeterminate-quarantine disposition. Persistent state and all evidence remain.

Outcome classes control progression exactly:

- `SEMANTIC_PASS`: complete scorable output/trace and protocol behavior passes; seal T/K/H and
  continue.
- `SEMANTIC_FAIL`: complete scorable output/trace within a proven boundary, but expected action,
  abstention, freshness, attribution, or other scorer condition fails; seal T/K/H and continue.
  It is an honest result, never a retry trigger.
- `CONTROLLED_HARNESS_FAILURE`: containment and termination are proven, but no complete scorable
  observation exists (for example authenticated client failure); seal T/K/H, create no later claim,
  and publish only a partial terminal disposition.
- `CONTAINMENT_FAULT`: manifest/runtime drift, secret/canary/egress breach, claim/chain defect,
  watchdog fault, missing evidence, or unproven termination; stop/quarantine, create no later claim,
  and publish only `SPENT_INDETERMINATE` partial disposition.
- `REVOKED_UNSTARTED` or `INELIGIBLE`: no provider claim; publish only a terminal disposition.

The successful collection artifact is named and labeled
`AUTOMATED_30_ADMISSION_COMPARISON_COMPLETED_UNREVIEWED`. It may exist only after exactly 30 claims,
30 complete scorable T receipts (`SEMANTIC_PASS` or `SEMANTIC_FAIL`), 30 K receipts, exact H[30],
all phase receipts, and no containment fault. It does not mean Engram won or a human reviewed it.

Every earlier stop uses a different path and schema named `partial-terminal-disposition-v1`. It
binds the last H, every claim/outcome, never-claimed ordinals, cause, object disposition, and
remaining absence. It must not contain comparison/Pareto/flagship-complete fields or use the
30-admission completion label. No partial evidence is promoted by inference or replay.
