## Authentication contract

Protocol schema v2 freezes `codex_authentication_mode: chatgpt_browser_keyring`. Each of the three
Codex lanes has a distinct mode-`0700` `CODEX_HOME`, an empty
`required_secret_environment`, and exact secret-free `login_argv` and `status_argv` values using:

```text
codex login --config 'cli_auth_credentials_store="keyring"'
codex login --config 'cli_auth_credentials_store="keyring"' status
```

The runner re-attests those exact commands and every Codex provider argv, rejects an `auth.json`
inside any lane home, rejects token or API-key requirements in keyring lanes, and removes
`CODEX_ACCESS_TOKEN` and `OPENAI_API_KEY` from keyring-backed Codex child processes. Before any
provider starts, it checks all Codex lanes; immediately before each Codex invocation, it checks that
lane again. Readiness requires a successful status command reporting exactly
`Logged in using ChatGPT`. Raw status output is never persisted.

The provider-free readiness check currently reports `not_logged_in` for Codex lanes 2, 4, and 6,
which is the expected state before the operator completes the browser flow. No existing
`~/.codex/auth.json` was read or copied, and no `auth.json` exists anywhere in the prepared tree.
