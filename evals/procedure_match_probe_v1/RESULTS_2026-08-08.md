# Procedure-match probe v1 results — 2026-08-08

The frozen real-matcher baseline **failed five gates**. The proof and prerequisite machinery was
strong, but two deliberately conflicting project/cwd scenarios returned the other repository's
verified procedure. That is a direct flagship safety failure and justifies a minimal fail-closed
production correction before any native-harness pilot.

## What passed

- Exact verified integration and deploy matches returned one correct procedure.
- Stable repository identity found the same integration procedure from a moved worktree.
- An unrelated but condition-compatible integration procedure did not contaminate the deploy
  task result.
- Missing and mismatched prerequisites abstained with explicit reasons.
- Missing, tampered, expired, and incomplete proof all abstained with the expected reason.
- A superseded active version was not returned.
- The verified failure signature matched its procedure, and a condition mismatch abstained.
- An unrelated Android query and a completely unscoped query abstained.

## Failures

1. With explicit project `atlas` and an Orbit cwd, the matcher returned
   `procedure-orbit-worker-deploy`.
2. With explicit project `orbit` and an Atlas cwd, it returned
   `procedure-atlas-worker-deploy`.

`resolve_orientation_project` records those conflicts as ambiguity, but `match_procedures` ignores
that ambiguity. Repository-scoped applicability then follows stable cwd identity, overriding the
caller's explicit project for the returned procedure. Both procedures had valid receipts and
conditions; proof validity therefore amplified a scope error instead of preventing it.

The superseded-version request correctly abstained but emitted no candidate diagnostic because the
active procedure did not cross the text-match threshold and inactive procedures are filtered before
diagnostics. This is an explanation gap, not an unsafe application. The single p95 violation was the
first/cold 54.70 ms query; the remaining local measurements do not justify changing the matcher or
the frozen latency gate.

## Decision

- Add one fail-closed guard to `match_procedures`: if repository/project resolution requires
  confirmation or reports material ambiguity, return an explicit abstention before ranking any
  procedure.
- Preserve the existing task threshold, condition comparison, receipt hash, expiry, lifecycle,
  and result-limit behavior; this baseline does not justify changing them.
- Add direct regression coverage for both explicit-project/cwd conflict directions.
- Re-run the unchanged 19-scenario matrix against source-attested corrected code. Do not relax the
  original outcome, diagnostic, or latency gates; report remaining non-safety failures separately.

This baseline does not authorize command execution or a host adapter. The provider-backed
Codex/Claude pilot remains separately approval-gated.
