# Coding-agent reviewer-authority gate v1 — 2026-08-08

## Outcome

The current Engram 0.2.3 candidate explicitly gates reviewer authority away from the ordinary
coding-agent profile. A Codex, Claude Code, or other client connected through the agent profile may
capture a proposal with file, commit, tool, URL, document, session-event, or observation evidence.
It may not submit `manual_review` evidence or call promotion, rejection, supersession, commit,
migration-review, or other administrative actions.

This closes a concrete gap: `manual_review` was already represented in trust metadata as an
unverified assertion, but the agent profile still accepted it. Storage capture policy could then use
the assertion when deciding whether some review-required claims became active. The proxy now rejects
the field before forwarding the request, including case-varied raw JSON that bypasses the advertised
schema.

The full profile retains the legacy review-assertion operations for an explicitly selected local
operator/admin session. Their free-form reviewer labels remain auditable assertions, not verified
human identity: derived trust metadata continues to report `reviewed=false` and
`review_state=active_unreviewed`.

## Enforced contract

- The agent-profile `memory.add.evidence[].kind` schema enumerates only source-evidence kinds and
  does not advertise `manual_review`.
- Request validation scans raw `memory(action=add)` arguments and rejects `manual_review`
  case-insensitively before daemon forwarding.
- Existing review-changing memory actions remain absent from the six-tool agent-profile allowlist.
- Initialization instructions tell the agent that it may propose guidance but cannot assert manual
  review or invoke review-changing actions.
- The runtime contract schema is now v3 and includes `review_authority_rejected` alongside the
  existing restricted-administrative-tool probe.

## Boundary of the claim

The proxy gate is a capability boundary for normal coding-agent sessions, not cryptographic human
authentication. A user who deliberately starts the full profile has selected an administrative
surface whose reviewer labels remain unverified. Engram still has no signed or host-attested human
review channel, so no caller-controlled field produces `review_state=reviewed`.

This gate also does not prove that an agent truthfully classified a claim as `user_stated` or
`user_corrected`; writer provenance and source evidence remain visible so retrieval can explain and
the user can correct the claim. A future verified-review design should begin with a host-controlled
capability or signed confirmation, not another free-form reviewer string.
