**Engram value assessment — September 18, 2026**

Engram implements useful memory-management mechanisms, but the available evidence does not establish a general productivity advantage over good instruction files, skills, and native harness memory. Its strongest comparison against an equally informed file-and-skill baseline found identical outcomes with higher agent cost. A narrow learned-procedure example improved Codex execution; repeated experiments improved structured identity and evidence routing. Neither establishes that the full architecture earns its cost on ordinary coding work.

This assessment distinguishes implementation, historical experiment results, fresh measurements, and untested hypotheses. No production code or configuration was changed for this assessment.

**The appropriate baseline is already capable.** `AGENTS.md` and `CLAUDE.md` supply persistent instructions; native memory adds learning across sessions. Claude documents an automatically maintained index plus topic files read on demand, with memory shared across worktrees of a repository. Codex documents local extraction and consolidation of durable entries and supporting evidence; its memory is off by default. Persistence, agent-written notes, selective loading, and evidence references therefore cannot by themselves distinguish Engram. These are documented capabilities, not comparative accuracy measurements. Sources: [Claude memory](https://code.claude.com/docs/en/memory), [Codex memories](https://learn.chatgpt.com/docs/customization/memories), [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), fetched September 18.

A fair alternative also includes a small shared Markdown index, ordinary file search, and a skill for applying procedures. Shared files can be used by several harnesses. Engram's advantage must come from making that work more reliable or less expensive, rather than merely making it possible.

Several distinctions matter. Structured MemoryItem retrieval is currently [lexical matching](/Users/yuval.meiri/projects/engram/engram-index/src/memory_ranker.rs:632); document semantic search is a separate path. General review freshness is advisory, whereas procedure expiry can reject a procedure. A verification receipt contains reported command/exit/output fields: hashing it detects changes, not fabrication or inadequate tests. The ordinary Codex adapter is advisory and still depends on the agent following instructions. An external database does not remove that dependency.

The native pilots contain causal limitations. Engram teaching receives a fully specified write and evaluator verification, while native teaching relies on automatic persistence. Engram adapters also provide extra routing instructions. Thus these compare packaged workflows; they do not isolate a database advantage or autonomous capture quality. In schema 15, combined arms lacked competing evidence-bearing native memory, so they did not test overriding stale native guidance. One native lane read the right runbook but failed the exact single-read/path contract. The reporter's positive "portable incremental value" label must not be read as proof of better coding outcomes. See [teaching construction](/Users/yuval.meiri/projects/engram/engram-eval/src/native_pilot.rs:2467) and [documented trace limitations](/Users/yuval.meiri/projects/engram/evals/native_memory_pilot_v1/SCHEMA15_EXACT_BASH_COMPLETED_2026-09-05.md:84).

The guard experiment also uses a toy executable that checks its arguments and prints a success marker. It is credible evidence of command selection and abstention, not a test of fixing a real defect. Its strong baseline does not prove that files will remain equally cheap to maintain over years or across many repositories.

**Recommendation.** Use instruction files for stable rules and build/test conventions, and native memory plus indexed files for ordinary session continuity. Engram is most plausibly justified where a shared, explicitly managed body of corrected knowledge across harnesses prevents recurring mistakes or saves substantial rediscovery. That benefit remains unproven against a comparably equipped shared-file baseline. There is no evidence here that the seven-layer architecture as a whole, graph storage, or semantic retrieval improves coding productivity. Keep existing useful data and mechanisms; do not infer from this assessment that they should be deleted. Additional product work should follow a measured failure of the strong baseline.

**A discriminating next evaluation is small and executable by coding agents.** Use three arms: (A) instructions + skills + enabled native memory; (B) A + shared indexed Markdown; (C) A + Engram with equivalent retrieval/capture guidance. B versus C is the decisive comparison. Beating A alone on cross-harness transfer would establish the benefit of shared memory, not Engram specifically.

Use four held-out fixes with hidden executable acceptance tests, two in each Claude-to-Codex / Codex-to-Claude direction, and two independently reset variants: **4 tasks × 3 arms × 2 variants = 24 reader sessions**, plus separately accounted teaching/activation work. Include a compatibility correction, two similarly named repositories with conflicting rules, an unfinished handoff, and a no-memory-needed control. Use opaque fixture names and forbid access to reference patches/hidden tests. Prefer resolved real defects with independently verified truth; label any synthetic cases. Pin the same model, reasoning, permissions, and limits within every matched reader comparison.

Each memory-dependent episode teaches a fact, later corrects it, interleaves approximately 200 identical relevant/distractor notes, then asks a fresh agent to implement the fix. The no-memory-needed control receives irrelevant notes only, with no useful teaching or correction. Do not place the answer in the evaluation prompt. Give the file arm a good index, aliases, scope, dates, source links, ordinary search, and an equivalent procedure skill. Give both shared stores the same information and maintenance opportunities. Verify native memory is enabled and has had an eligible consolidation opportunity; hold the reader's native starting state equal between B and C.

First run an equal-content retrieval/use track to isolate storage and selection. Then run autonomous capture only if warranted, recording capture failures rather than secretly repairing them. Score **final patch correctness** with hidden acceptance and regression tests; separately report whether the correction was stored, current evidence retrieved, stale guidance used, and wrong-scope commands attempted. Do not award task-success credit for reproducing Engram-specific IDs, enums, or exact tool routes. Accept equivalent evidence reads.

Count teaching, retrieval, corrections, maintenance interventions, tool calls, total and uncached tokens, elapsed time, and measurable background-memory work. Unknown background costs stay unknown. For this pilot, define efficiency in advance as summed matched reader total tokens and summed matched reader wall time, reported separately within each reader harness. Charge shared teaching/update work across exactly the two evaluated readers per task, and separately show reader-only figures; do not choose a longer reuse horizon after seeing results. Do not convert tokens into money without verified prices and cache accounting.

Freeze a provisional stop rule before outcomes: if C adds no correct solutions over B and saves neither accounted tokens nor accounted elapsed time by at least 20%, stop with "no demonstrated incremental value in this pilot." Require no new stale-guidance or wrong-scope unsafe action under either expansion route. Two additional correct solutions among eight pairs, or at least 20% efficiency improvement without accuracy loss or regression in the other resource metric, justify expansion rather than a product claim. Require the direction of any efficiency benefit to agree across both reader harnesses. Expand to at least 20 distinct unseen tasks with three repetitions and paired task-level uncertainty estimates; repetitions are not independent tasks. Freeze any adoption threshold before that expansion.

This new coding-outcome pilot is **designed, not executed**. Existing evidence already answers the narrower guard question negatively; another repetition of that same optimized toy fixture would add less information than testing correction and handoff on real patches.
