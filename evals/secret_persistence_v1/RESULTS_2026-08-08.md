# Secret persistence gate v1 — 2026-08-08

## Outcome

The current Engram 0.2.3 worktree passes the flagship canary gate on a real temporary RocksDB
store. Synthetic bearer-token and secret-assignment canaries were submitted through three MCP
memory write paths:

- ordinary durable memory `add`;
- structured procedure-candidate `add`, with the canary in an executable command;
- `capture_current_plan` with knowledge-commit creation enabled.

Every call returned the storage-boundary policy error `secret material was not persisted`. The test
then verified that the RocksDB store had been materialized and that both canonical projections—
memory items and knowledge commits—remained empty. No canary appeared in either response.

The test does not use, restart, or modify the installed live daemon or `~/.engram/data`.

## Storage-boundary coverage

`engram-store/src/secret.rs` recursively checks serialized fields, nested values, map keys, and
credential-shaped field names. The current detector recognizes:

- private-key blocks;
- bearer credentials;
- credential-bearing URLs;
- common secret assignments;
- AWS, GitHub, Slack, and `sk-` token shapes;
- JWT-shaped values.

Canonical guidance stores reject likely secrets. Operational history that must remain fail-open,
such as sessions and harness telemetry, redacts likely secret fields before persistence and emits a
warning. Repository tests cover memory metadata and procedure fields, knowledge commits, entities,
work records, repository topology, documents, knowledge records, tool intelligence, sessions,
coordination, obligations, and telemetry.

## Boundary of the claim

This proves that the preregistered canary classes do not reach durable flagship projections. It is
not a universal data-loss-prevention claim: an unknown credential format or sufficiently
unstructured high-entropy secret may evade heuristic classification. Authoritative host and
connector boundaries must still avoid sending credentials to Engram, and future new persistence
repositories must apply the same storage-boundary policy.
